# בוט משרדי לוואטסאפ – ניהול משימות, יומן ודרייב

בוט שמצטרף כחבר רגיל לקבוצת הוואטסאפ של המשרד (דרך המספר הנוסף שלך), קורא הודעות,
מזהה משימות/תזכורות/בקשות ליומן ולדרייב, ושולח סיכומים תקופתיים – תוך שימוש חסכוני בטוקנים.

## ⚠️ חשוב לפני שמתחילים

הבוט מתחבר לקבוצה דרך ספריה לא-רשמית (Baileys) שמדמה מכשיר וואטסאפ רגיל.
זה **נגד תנאי השימוש של WhatsApp**. הסיכון לחסימה נמוך יחסית בשימוש משרדי שקט,
אבל קיים. מומלץ:
- להשתמש במספר שאינו קריטי לכם (לא המספר האישי הראשי)
- לא לשלוח כמויות גדולות של הודעות אוטומטיות ברצף
- לגבות מדי פעם את `office.db` (המשימות) – הוא לא תלוי בוואטסאפ

## שלב 1: התקנה מקומית (לבדיקה)

```bash
npm install
cp .env.example .env
```

מלא ב-`.env`:
- `ANTHROPIC_API_KEY` – מפתח מ-console.anthropic.com
- `AUTHORIZED_NUMBERS` – המספרים של אורטל, מורן, אורון והילה, בפורמט בינלאומי בלי + (למשל 972501234567)

## שלב 2: חיבור המספר הנוסף לוואטסאפ

```bash
npm start
```

יופיע קוד QR בטרמינל. מהמספר הנוסף: **וואטסאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר**, וסרוק.
לאחר החיבור הראשוני זה נשמר בתיקיית `auth_info/` ולא תצטרך לסרוק שוב (כל עוד לא מתנתקים).

## שלב 3: הוספת הבוט לקבוצה ומציאת ה-ID שלה

1. בקש מאורטל (או מי שמנהל את הקבוצה) להוסיף את המספר הנוסף שלך כחבר רגיל בקבוצת המשרד.
2. שלח בקבוצה את ההודעה: `/קבוצות`
3. הבוט ישלח לך רשימת קבוצות עם ה-ID של כל אחת. העתק את ה-ID של קבוצת המשרד (מסתיים ב-`@g.us`).
4. הדבק אותו ב-`.env` תחת `OFFICE_GROUP_ID`, והפעל מחדש את הבוט.

## שלב 4: חיבור Google (יומן + דרייב)

1. היכנס ל-[Google Cloud Console](https://console.cloud.google.com/), צור פרויקט חדש.
2. הפעל את **Google Calendar API** ו-**Google Drive API**.
3. צור **Service Account** (IAM & Admin → Service Accounts → Create), והורד את קובץ ה-JSON.
4. שים את הקובץ בתיקיית הפרויקט בשם `google-service-account.json`.
5. שתף את **יומן המשרד** ואת **תיקיית הדרייב** עם כתובת המייל של ה-Service Account
   (נראית כמו `xxx@yyy.iam.gserviceaccount.com`) – בדיוק כמו ששותפים עם עמית לעבודה.
6. מלא ב-`.env` את `GOOGLE_CALENDAR_ID` ו-`GOOGLE_DRIVE_FOLDER_ID`.

## שלב 5: פריסה לאחסון קבוע (מומלץ: Railway)

למה Railway: זול (כ-5$/חודש בשימוש קל), תומך ב-**Persistent Volume** (חשוב! –
בלי זה, `auth_info/` ו-`office.db` יימחקו בכל דיפלוי מחדש ותצטרך לסרוק QR שוב).

1. העלה את הפרויקט ל-GitHub (repo פרטי).
2. ב-[railway.app](https://railway.app): New Project → Deploy from GitHub repo.
3. הוסף **Volume** (Settings → Volumes), עם mount path: `/app/auth_info` ועוד אחד ל-`/app` (או פשוט mount על כל התיקייה שמכילה גם את `office.db`).
4. הוסף את משתני הסביבה מ-`.env` תחת Variables (כולל תוכן קובץ ה-Google JSON – אפשר כמשתנה טקסט ולשמור אותו כקובץ ב-build, או להעלות את הקובץ ל-Volume ידנית).
5. Deploy. עקוב אחרי הלוגים כדי לסרוק את ה-QR (בפעם הראשונה בלבד).

חלופות זולות דומות: Render, Fly.io (יש להן גם volumes).

## איך זה חוסך טוקנים (הבעיה שהייתה ב-Make)

1. **אין שליחת היסטוריה מלאה** – רק "סיכום גלגלי" קצר (`rolling_summary`) נשמר ומתעדכן, במקום כל השיחה.
2. **ניתוב לפי מורכבות** – הודעה נכנסת קודם עוברת סיווג עם Claude Haiku (זול, מהיר).
   רק אם באמת צריך ניסוח/הבנה מורכבת עוברים ל-Sonnet.
3. **Prompt Caching** – ה-system prompt הקבוע מסומן ב-`cache_control`, כך שהוא לא נטען
   (ולא משלמים עליו) מחדש בכל קריאה.
4. **סמול-טוק לא מפעיל AI שני** – תגובות כמו "תודה" מקבלות 👍 בלי לקרוא למודל שוב.
5. **סינון לפי מספר מורשה** – הודעות ממי שלא ברשימת המורשים לא מגיעות ל-AI בכלל.
6. **max_tokens נמוך** לרוב הקריאות – אין תשובות מנופחות.

## מבנה הפרויקט

```
src/
  index.js        – חיבור הכל יחד
  whatsapp.js      – חיבור לוואטסאפ (Baileys), שליחה/קבלה
  ai.js            – קריאות ל-Claude, ניתוב מודלים, caching, סיכום גלגלי
  google.js        – יומן גוגל + דרייב
  db.js            – SQLite: משימות, תזכורות, לוג הודעות
  taskHandler.js   – הלוגיקה שמחליטה מה לעשות עם כל הודעה מסווגת
  scheduler.js     – תזכורות + סיכומים יומיים/שבועיים אוטומטיים
```

## פקודות שימושיות בקבוצה

- כל משפט טבעי כמו "תזכירי לי להגיש את התביעה של כהן עד יום שלישי" – נוצרת משימה + תזכורת
- "תוסיפי ליומן פגישה עם לקוח מחר ב-10" – נוצר אירוע ביומן
- "תמצאי לי את החוזה של דוד לוי" – חיפוש בדרייב
- "מה המשימות הפתוחות" / "סיכום יומי" – סיכום מיידי
- `/קבוצות` – פקודת עזר חד-פעמית למציאת ה-ID של הקבוצה

## מה עוד כדאי לשפר בהמשך

- זיהוי "מי שלח" לפי שם (לא רק מספר) – למשל למפות `assigned_to` אוטומטית
- ממשק ווב קטן לצפייה במשימות (כרגע רק דרך וואטסאפ)
- גיבוי אוטומטי של `office.db` לדרייב המשרדי
